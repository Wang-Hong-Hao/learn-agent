# ReAct 调度引擎（Agent Loop）
## 1.ReAct 模式 是 Reason（思考推理） + Act（行动执行） 的缩写
普通 Chatbot 只是“一问一答”：
而 Agent 的工作流是一个**“状态机循环（Loop）”**：
┌───────────────────────────────┐
│        用户提出任务           │
└───────────────┬───────────────┘
                │
                ▼
┌─────────────────────────────────────┐
┌──────────>│       1. 请求大模型 (Reason)        │
│           │ 模型阅读当前所有历史，决定下一步操作│
│           └──────────────────┬──────────────────┘
│                              │
│                              ▼
│                      【判断是否有工具调用？】
│                       /             \
│             [有工具调用]             [没有工具调用]
│                   /                     \
│                  ▼                       ▼
│    ┌──────────────────────────┐    【任务达成！】
│    │   2. 执行本地函数 (Act)  │     退出 while 循环
│    │  校验危险 -> 执行本地 TS  │     向用户返回最终答案
│    └─────────────┬────────────┘
│                  │
│                  ▼
│    ┌──────────────────────────┐
│    │   3. 追加结果到上下文    │
└────┤ role: "tool", content:.. │
└──────────────────────────┘
## 2. 关键细节：大模型对话历史中的 4 种角色（Role）

大模型的聊天上下文是一个数组 `messages`。每一条消息都有一个 `role`（角色）：

`system`：系统人设（例如：“你是一个高效的 AI 助理...”）。
`user`：用户输入的指令（例如：“帮我统计 package.json 有几个依赖”）。
`assistant`：大模型自己说的话。
如果它决定调工具，它的消息里会包含 `tool_calls`。
`tool`（最关键！）：
当你在本地跑完工具后，你必须以 `role: "tool"` 构造一条消息，并带上这条工具调用的 ID（`tool_call_id`），把结果塞进 `messages`。
大模型看到这条 `tool` 消息，才知道“哦，原来刚才我调用的函数返回了这串内容”，从而继续思考下一步！


## 3.maxSteps（熔断机制）
如果大模型犯傻了，陷入死循环（比如一直重复调同一个错误的工具），你的代码会无限循环请求，导致你的 API 额度被瞬间扣光！
因此，每个合格的 Agent 都必须有一个 `maxSteps` 熔断步数（比如最多只允许循环 10 次，超时强制抛出异常）。
